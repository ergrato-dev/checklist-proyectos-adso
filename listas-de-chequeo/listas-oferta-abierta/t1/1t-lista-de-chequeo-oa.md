> **Naturaleza de esta sesión:** Esta no es una sesión de evaluación técnica
> sino una sesión de **aprobación de ideas de proyecto**. El equipo presenta,
> el jurado escucha, pregunta y decide. El resultado es binario: la idea es
> aprobada (con o sin condicionamientos) o devuelta para reformulación con
> plazo de una semana calendario. Esta sesión cubre los primeros Resultados
> de Aprendizaje del programa: RA01 de Gestión de Procesos (caracterización
> del negocio), RA02 (identificación de necesidades del usuario) y prepara
> el terreno para RA03 de Programación (delimitación del alcance funcional).

## Bloque A — Constitución del equipo

> **Prerequisito de entrada.** Estos ítems deben cumplirse antes de iniciar
> la presentación de ideas. Si alguno no se cumple, el grupo no accede a la
> sesión y se le asigna una fecha de reintento dentro de la misma semana.

| #   | Criterio | ✅ Cumple | 🔴 No cumple | Observación |
|-----|----------|-----------|--------------|-------------|
| A.1 | El grupo tiene entre 3 y 5 integrantes. Se recomienda número impar para facilitar la toma de decisiones colectivas por mayoría simple. | | | |
| A.2 | Cada integrante se presenta con nombre completo y puede identificar a todos sus compañeros de grupo por nombre. | | | |
| A.3 | El grupo tiene un nombre de equipo y ha designado un vocero o líder para esta sesión. El rol puede rotar en trimestres siguientes. | | | |
| A.4 | **El grupo tiene cinco integrantes (fuertemente recomendado en primer
trimestre).** Grupos de tres son el mínimo aceptable solo cuando el número
total de aprendices de la ficha no permite conformar grupos de cinco. El
instructor debe registrar la justificación si aprueba un grupo de menos de
cinco integrantes. *Nota pedagógica: un curso de 30 aprendices con grupos
de cinco genera 6 equipos; con grupos de tres genera 10. La diferencia no
es cosmética: con 6 equipos el instructor puede dar feedback profundo y
personalizado en cada seguimiento; con 10 equipos el tiempo de atención
por grupo se reduce a menos de la mitad, lo que deteriora directamente la
calidad del proceso formativo. Forzar grupos de cinco en primer trimestre
es, antes que una restricción, una decisión de calidad pedagógica.* | | | |

## Bloque B — Presentación de ideas

> El grupo presenta **tres ideas de proyecto priorizadas** (Idea 1 = preferida,
> Idea 3 = alternativa), cada una en un **dominio diferente**. El jurado evalúa
> cada idea de forma independiente con los mismos criterios. No se requieren
> diagramas, wireframes ni código: solo claridad conceptual y conocimiento
> mínimo del dominio propuesto.

| #   | Criterio de evaluación | Idea 1 | Idea 2 | Idea 3 | Observaciones del jurado |
|-----|------------------------|--------|--------|--------|--------------------------|
| B.1 | El grupo enuncia claramente el **problema** que el software resuelve —no la solución, sino el problema— en máximo tres frases. | ☐✅ ☐🔴 | ☐✅ ☐🔴 | ☐✅ ☐🔴 | |
| B.2 | El grupo identifica al menos un **usuario real o tipo de usuario** que tiene ese problema hoy, de forma concreta y no genérica. | ☐✅ ☐🔴 | ☐✅ ☐🔴 | ☐✅ ☐🔴 | |
| B.3 | El grupo puede narrar un **ejemplo de uso cotidiano** del software propuesto, aunque sea de forma informal y sin artefactos de diseño. | ☐✅ ☐🔴 | ☐✅ ☐🔴 | ☐✅ ☐🔴 | |
| B.4 | El grupo menciona al menos un **software existente similar** y puede explicar en qué se diferenciaría su propuesta, así sea brevemente. | ☐✅ ☐🔴 | ☐✅ ☐🔴 | ☐✅ ☐🔴 | |
| B.5 | El alcance propuesto es **realizable por un equipo de 3 a 5 personas a lo largo del programa formativo**, sin depender de infraestructuras, presupuestos o tecnologías inalcanzables. | ☐✅ ☐🔴 | ☐✅ ☐🔴 | ☐✅ ☐🔴 | |

## Bloque C — Líneas rojas: dominios con restricción

> Las líneas rojas no son caprichos del instructor ni del jurado: son criterios
> pedagógicos y profesionales documentados y defendibles. Una idea que incurra
> en una línea roja absoluta se descarta de inmediato con retroalimentación
> clara al grupo sobre por qué y hacia dónde redirigir la propuesta. Las líneas
> rojas condicionales requieren que el grupo cumpla la condición señalada en
> la misma sesión o en el plazo de reformulación.

### C.1 — Restricciones absolutas (rechazo automático)

| Dominio restringido | Justificación pedagógica y profesional | ¿Aplica Idea 1? | ¿Aplica Idea 2? | ¿Aplica Idea 3? |
|---------------------|----------------------------------------|-----------------|-----------------|-----------------|
| **Inventarios** | Dominio saturado con soluciones industriales gratuitas y maduras (Odoo Community, ERPNext, entre otras). Construir un sistema de inventarios en 2025 no demuestra capacidad de resolver problemas complejos ni diferencia al egresado en el mercado laboral. Ninguna empresa que pueda contratar un desarrollador le pedirá construir esto desde cero. | ☐ Sí ☐ No | ☐ Sí ☐ No | ☐ Sí ☐ No |
| **Contabilidad** | Requiere cumplimiento de normativas técnicas y legales estrictas (PUC, NIIF, regulaciones DIAN) que están fuera del alcance formativo. Un sistema contable incorrectamente implementado puede causar daño económico real a quien lo utilice, lo que genera una responsabilidad que el proyecto formativo no puede asumir. | ☐ Sí ☐ No | ☐ Sí ☐ No | ☐ Sí ☐ No |
| **Facturación electrónica** | Regulada en Colombia por la DIAN mediante esquemas XML certificados, numeración controlada y validación previa obligatoria. No es implementable correctamente en un proyecto formativo sin riesgo de consecuencias legales reales para quien lo utilice o lo emita. | ☐ Sí ☐ No | ☐ Sí ☐ No | ☐ Sí ☐ No |

### C.2 — Restricciones condicionales (aprobación sujeta a condición)

| Dominio restringido | Condición de aprobación | Decisión Idea 1 | Decisión Idea 2 | Decisión Idea 3 |
|---------------------|-------------------------|-----------------|-----------------|-----------------|

## Bloque D — Competencias transversales en la presentación

> Aunque T1 no evalúa artefactos técnicos, la presentación oral es en sí misma
> una evidencia de competencias blandas que forman parte integral de los RAPs
> de Gestión de Procesos: comunicación con el cliente, argumentación de
> decisiones y trabajo colaborativo. El jurado registra su percepción con
> la escala de cuatro niveles.

**Escala:** ✅ Excelente — 🟡 Satisfactorio — 🔴 Insuficiente — ➖ No aplica

| #   | Criterio | ✅ | 🟡 | 🔴 | ➖ | Observaciones |
|-----|----------|----|----|----|----|----|
| D.1 | **Participación distribuida:** todos los integrantes toman la palabra durante la presentación; no es una exposición individual del líder con los demás como espectadores. | | | | | |
| D.2 | **Solidez ante preguntas:** el grupo responde las preguntas del jurado sin colapsar, sin contradicciones evidentes y sin delegar todas las respuestas al mismo integrante. | | | | | |
| D.3 | **Preparación mínima del dominio:** el grupo demuestra que investigó el contexto del problema propuesto antes de la sesión; las ideas no parecen improvisadas en el momento. | | | | | |
| D.4 | **Actitud ante el feedback:** el grupo recibe las observaciones del jurado con apertura constructiva, hace preguntas de clarificación si no entiende algo y no adopta una postura defensiva o cerrada. | | | | | |
